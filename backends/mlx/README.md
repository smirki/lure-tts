# lure-mlx

The Apple silicon backend for Lure TTS. It runs on MLX and uses the Qwen3-TTS modules from
[mlx-audio](https://github.com/Blaizzy/mlx-audio) (MIT, see `LICENSE-mlx-audio`), pinned to commit
`402e3b9e4bd9bbecedc917b290896e5588c76f58`, with `mlx==0.32.4`.

Supported: every Qwen3-TTS 12Hz checkpoint (0.6B and 1.7B; Base, CustomVoice, VoiceDesign) and the Lure family,
in the `icl`, `xvec`, `custom_voice` and `voice_design` modes, each in the non-streaming and streaming layouts.
Verified with the conformance suite on an Apple M5: Lure voice cloning (`icl`, non-streaming layout, 0.6B), with the
speaker-similarity gap listed under known limitations. The stock checkpoints and the other modes are tested on tiny
random-weight fixtures, including greedy parity with qwen-tts 0.1.1; real-weights reports are welcome via GitHub
issues. The Turbo head (0.6B Lure family) is checked against the reference fixture.

The adapter loads mlx-audio's modules (talker, code predictor, speech tokenizer, speaker encoder) and runs its own
generation loop. The prompt comes from the core's prompt rows, so it matches the reference layout, and sampling uses
the model's own settings. The contract is in [docs/architecture.md](../../docs/architecture.md#backend-contract).

Full documentation: [docs/backends/mlx.md](../../docs/backends/mlx.md).

## Install

macOS on Apple silicon, Python 3.10 or newer. From the repository root:

```bash
pip install ./backends/mlx ".[server]"
```

```bash
lure say "Hello there. (laugh) Really?" --backend mlx --model /path/to/lure \
    --ref-wav ref.wav --ref-text "Transcript of ref.wav." -o out.wav \
    --opt cache_limit_mb=128 --opt memory_limit_gb=3.5
```

## Layout

| file | contents |
|---|---|
| `lure_mlx/backend.py` | `MLXBackend`: load (any variant and size, checked against the spec), `encode_voice` (Base), `generate` (every mode and layout, streamed or whole), `dump_layout`, quantization |
| `lure_mlx/embed.py` | prefill embeddings built from the core's prompt rows |
| `lure_mlx/sampling.py` | on-device logits pipeline: repetition penalty, token suppression, EOS mask, temperature, top-k, top-p, Gumbel-max sampling |
| `lure_mlx/cp.py` | code predictor for codebooks 1 to 15, eager and compiled (`compile_cp=1`) |
| `lure_mlx/turbo.py` | the Turbo head (3 grouped passes instead of 15 sequential steps) |
| `tests/tiny.py` | tiny random-weight checkpoints for every variant, 0.6B and 1.7B shapes |
| `tests/test_modes_tiny.py` | load, prompt rows, embeddings, greedy parity with qwen-tts (`fixtures/qwen_greedy.json`, regenerated by `make_qwen_fixture.py` + `qwen_worker.py`), decode paths, public API |
| `tests/test_mlx_tiny.py`, `tests/test_turbo_tiny.py` | sampling, code predictor, generation paths; the Turbo head against `conformance/turbo/fixtures/tiny_turbo.*` |
| `tests/real_modes.py` | optional manual run of every mode of one real checkpoint (not collected by pytest) |

## Tests

The tests build a tiny random talker and never load the real checkpoint. They need the repository checkout because
they read the tokenizer and prompt fixtures from `conformance/reference/`.

```bash
pip install -e ".[dev]" -e "./backends/mlx[test]"
python -m pytest backends/mlx/tests
```

183 tests, about 25 s and under 1 GB peak on an Apple M5. The parity tests run on the MLX CPU device because Metal
float32 matmuls are not full fp32 precision (about 1e-2 logit error against 5e-5 on the CPU), and a tolerance loose
enough for Metal would hide real bugs.
